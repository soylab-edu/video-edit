# 로컬 개발로 이전

현재 실행 중인 `/workspace/video-edit`는 클라우드 작업실입니다. Codex 데스크톱 앱에서 기존 대화를 열어도 이 실행 환경이 자동으로 본인 PC로 옮겨지지는 않습니다. PC에 소스 폴더를 준비한 후, Codex에서 해당 **로컬 폴더를 작업 대상으로 열어** 개발해야 합니다.

2026-10-05 확인 시 원격 `main`에는 초기 커밋만 있었습니다. 저장소를 단순히 복제하는 것만으로 현재 편집기를 받았다고 가정하지 마세요. 현재 작업 소스의 전달 또는 Git 동기화가 먼저 필요합니다. 소스 전달본에는 `.data`, 비밀번호·Codex 토큰·사용자 미디어, `node_modules`, Python 환경 및 분리 모델을 포함하지 않습니다.

## 실행 방식

Windows에서는 Docker 없이 Node.js·FFmpeg·Python을 직접 사용하는 실행 경로를 검증했습니다. `scripts/setup-windows.ps1`로 의존성을 준비하고 `start-moa.cmd`로 실행합니다. [Windows 개발 환경 안내](windows-development.md)에 상세 명령과 검증 기록이 있습니다.

Docker Desktop(Windows/macOS) 또는 Docker Engine + Compose(Linux)는 선택적인 개발 방법입니다. Docker 구성은 아직 실제 PC에서 빌드·실행하지 않은 초안입니다. 아래 단계는 Docker 방법이며, 네이티브 Windows 실행기는 별도로 위 안내를 따릅니다.

1. 로컬 폴더에 최신 소스를 풀고 Docker를 실행합니다.
2. macOS는 `start-moa.command`를 실행합니다. Windows/Linux의 Docker 방법은 프로젝트 폴더에서 아래 명령을 사용합니다.

   ```bash
   docker compose up -d --build --wait --wait-timeout 180
   docker compose exec -T editor node scripts/invite.mjs http://localhost:3001
   ```

3. **본인 PC에서 직접 실행한 경우에만** 출력된 최초 설정 링크를 같은 PC의 브라우저에서 엽니다. 이 로컬 인스턴스는 별도 작업실이므로, 기존 데이터를 이전하지 않았다면 처음 한 번 비밀번호를 설정합니다. 현재 클라우드 작업실의 비밀번호는 변경하지 않습니다.
4. Codex 연결은 이 로컬 작업실에서 사용자가 직접 ChatGPT 로그인을 승인합니다. 클라우드 로그인 토큰을 소스에 넣거나 자동 복사하지 않습니다.
5. 코드 변경 후 같은 Compose 명령으로 다시 빌드할 수 있습니다. 이 방식은 자동 갱신되는 개발 서버가 아니라 재빌드 방식입니다. 중지는 `docker compose stop`, 다시 실행은 `docker compose up -d`입니다. 데이터 보존을 위해 `docker compose down -v`를 실행하지 마세요.

첫 빌드에는 Python/PyTorch 설치와 약 446 MB의 BandIt 체크포인트 다운로드가 포함되어 오래 걸릴 수 있습니다. 현재 Compose는 `linux/amd64`로 지정되어 있어 Apple Silicon에서는 에뮬레이션이 필요할 수 있습니다. PC의 운영체제·CPU와 사용 가능한 자원을 확인한 뒤 조정·검증하세요. 로컬 실행은 인터넷에 공개되지 않습니다. Runway는 승인된 선택 소재를 직접 업로드하는 경로를 구현했으며, 다른 제공업체에 참조 소재를 전달하려면 별도의 승인된 HTTPS 전송 경로가 필요합니다.

## 기존 작업 자료

클라우드 `.data/live-workspace`는 그대로 보존합니다. 프로젝트 JSON만으로는 영상·음원 파일까지 이전되지 않습니다. 실제 자료 이전은 로컬 실행을 먼저 확인한 후 별도 백업·복원으로 진행합니다. 토큰·세션을 포함하는 작업실 전체를 공개 저장소나 소스 전달본에 넣지 마세요.

## 최종 배포: 각자 PC에서 쓰는 프로그램

사용자는 중앙 웹서비스 운영을 원하지 않습니다. Windows에서 개발한 뒤 프로그램 자체를 다른 사람에게 전달해 각자 PC에서 실행하는 방향입니다. 보유 도메인이나 상시 서비스 서버는 이 목표의 필수 조건이 아닙니다. 중앙 가입·결제·다중 사용자 서버를 만드는 작업으로 범위를 확대하지 마세요.

현재 React 편집 화면과 로컬 Node/FFmpeg/Python 엔진을 기반으로, Windows 설치 파일과 자동 실행을 후속 구현합니다. Docker는 개발 환경을 맞추는 수단이며 최종 사용자의 필수 설치 항목으로 가정하지 않습니다. 현재 저장소에 완성된 `.exe` 설치 파일이나 설치형 앱이 있다는 뜻은 아닙니다.

배포본에는 각자의 작업실을 따로 만들고, 자료·비밀번호·Codex 로그인·플러그인 연결을 본인 PC에 보관합니다. 개발자의 작업실 데이터나 로그인 토큰을 포함하지 않습니다. FFmpeg 편집과 BandIt 분리는 PC에서 실행하고, Codex·TTS·생성 플러그인 같은 온라인 기능은 각자의 연결과 사용 조건을 따릅니다. 외부 생성의 소재 전송·비용 승인도 유지해야 합니다.

후속 Windows 패키징 검증에는 로컬 서버의 loopback 바인딩, 한 번만 실행하기, 앱 종료 시 자식 프로세스 정리, 사용자별 데이터 경로, FFmpeg/Python·모델 설치 및 업데이트, 한글 경로, 프로젝트 저장/복원, 생성 모델용 승인된 파일 전송 경로가 포함됩니다. 기존 `compose.server.yaml`·`Caddyfile`은 선택적인 서버 배포 초안으로 남기며 이번 배포 목표에 적용하지 않습니다.
